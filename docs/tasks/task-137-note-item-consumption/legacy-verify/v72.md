# v72 Note-Item Consumption — IDA Verification (FR-1)

Binary: `GMS_v72.1_U_DEVM.exe.i64` (IDA session `90e36cb0`, confirmed via `idb_list`).
Version: **GMS v72** (v72.1). Serverbound routing (from Atlas seed template):
`CharacterCashItemUseHandle` = 0x4E, `NoteOperationHandle` = 0x81.

**CASH-ITEM NOTE SEND ARM: PRESENT in v72**
**updateTime: TRAILING** (encoded after the strings, GMS<v87 idiom — matches v83)

## Cash-item note-send wire shape (opcode 0x4E)

| Field | Encoder | Width | Address | Notes |
|---|---|---|---|---|
| opcode | COutPacket ctor | u16 hdr | 0x905050 | immediate `push 4Eh` @0x90504B |
| slot position | Encode2 | int16 | 0x905062 | arg1 (nPOS) |
| itemId | Encode4 | int32 | 0x90506E | arg2 (== 5090000); also switch key |

| updateTime | Encode4 | uint32 | 0x909123 | **TRAILING**; `get_update_time()` @0x90911A |

Send: `sub_513573` (SendPacket) @0x90912C on the same `COutPacket` (var_3C).
This is byte-identical in field order to the known-good v83 shape.

## Deliverable 1 — Type gate for classification 509

**Address: 0x49FB33** (`sub_49FB33`, mislabeled `ZMap<...LOTTERYITEM>::GetAt`; it is the
itemId→cash-slot-type classifier, `switch(itemId/10000)`).

- `case 509: return 21;` at **0x49FC2E**.
- Wrapped by `is_select_npc_item` (0x49FACC), which validates the type is in a
  send-eligible range (21 ∈ 12..32 → passes through, not zeroed) @0x49FB01.
- Result 21 matches v83 exactly. Item 5090000 (class 509) → type **21**.

## Deliverable 2 — Note arm in SendConsumeCashItemUseRequest

**Function: 0x904FE2** `CWvsContext::SendConsumeCashItemUseRequest(long slot,long itemId,long,ZXString message)`.
Switch key = `is_select_npc_item(itemId) - 12`, 54 cases (jump `@0x905089`).
Type 21 → index 9 → **arm loc_905E83** (IDA labels it "case 21").

Arm 0x905E83:
- Allocates a memo-compose dialog object (`sub_71A0F8`, 0x9C bytes) @0x905E8D/0x905E9F,
  pre-filled from the passed message (arg_C) @0x905ECB–0x905EF9.
- Shows modal: `sub_4D91E8` @0x905F01 (DoModal-equivalent); returns 1 on OK — else
  jmp cleanup 0x90634F (no packet sent).
- On OK, `sub_71A761` @0x905F30 pulls two `CCtrlEdit::GetText` fields (recipient edit,
  message edit — verified in sub_71A761 @0x71A761), then:
  - **EncodeStr(toName)** @0x905F49
  - **EncodeStr(message)** @0x905F62
- `jmp loc_905294` (shared finalize/send tail).

Confirmed: opens a recipient/message modal and encodes `EncodeStr(toName)` then
`EncodeStr(message)`, matching v83.

## Deliverable 3 — updateTime position (leading vs trailing)

**TRAILING.** The memo arm jumps to `loc_905294`, which calls the send gate
`sub_4DBE16(this, 0x1F4)` @0x90529D; on success `jnz loc_90911A`. At the shared tail:
- `get_update_time()` @**0x90911A**
- `Encode4(updateTime)` @**0x909123** — emitted *after* both `EncodeStr` calls.
- SendPacket (`sub_513573`) @0x90912C.

updateTime is the last field before send → TRAILING (GMS<v87), matching v83.

## Deliverable 4 — Full encoded wire order

On the single `COutPacket(0x4E)` (var_3C):
1. Encode2(slot) — 0x905062
2. Encode4(itemId) — 0x90506E
3. EncodeStr(toName) — 0x905F49
4. EncodeStr(message) — 0x905F62
5. Encode4(get_update_time()) — 0x909123 (TRAILING)
→ SendPacket 0x90912C.

## Deliverable 6 — CWvsContext::OnMemoResult (clientbound)

**Function: 0x91D23D.** Dispatch: `mode = Decode1(a2)` @0x91D258, then a
subtract-chain (`mode-3`, `-1`, `-1` …).

| Mode | Meaning | Address | Body |
|---|---|---|---|
| 3 | SHOW / LOAD memo list | 0x91D317 | `ZList<GW_Memo>::RemoveAll`, `Decode1(count)`, loop `sub_4D0F8B` per GW_Memo; may pop "new memo" fade window |
| 4 | SEND_SUCCESS | 0x91D2FE | Notice StringPool 2693 |
| 5 | SEND_ERROR | 0x91D27F | `Decode1(errorCode)` @0x91D2A3, then Notice: |
| 7 | REFRESH / notify | 0x91D275 | → `OnMemoNotify_Receive` |
| 6, others | (ignored) | — | falls through, returns |

Mode 5 (SEND_ERROR) sub-error codes (`Decode1`):
- **0 → StringPool 2634** (receiver online) @0x91D2FA
- **1 → StringPool 2635** (receiver unknown) @0x91D2D2
- **2 → StringPool 2636** (inbox full) @0x91D2C0
- ≥3 → return (no notice)

**No "no note item" arm exists** — error handling only covers receiver-online /
receiver-unknown / inbox-full, as expected.

## Deliverable 7 — NOTE_ACTION writers (opcode 0x81)

Enumerated every `push 81h` (0x81=129) code site (12 total); exactly **3** construct a
`COutPacket(0x81)`. The remaining 9 are unrelated (WM_NCCREATE=0x81 in DialogFunc /
sub_638AA4 window procs; a StringPool id in SendChatMsgSlash @0x512C5A; a vcall arg in
sub_7D4C77 @0x7D4D85; runtime stubs sub_948C51/sub_948DBF).

| # | Writer | COutPacket ctor | Mode byte | Address |
|---|---|---|---|---|
| 1 | `CCashShop::OnCashItemResLoadGiftDone` | 0x47135E | **0** (gift SEND) | Encode1(0) @0x47136B |
| 2 | `CMemoListDlg::SetRet` | 0x5FB4C8 | **1** (discard/receive) | Encode1(1) @0x5FB4D5 |
| 3 | `CWvsContext::OnMemoNotify_Receive` | 0x91D3CE | **2** (request/notify) | Encode1(2) @0x91D3DC |

Matches the expected 3 writers. (Note: `OnCashItemResLoadGiftDone` @0x47122E is a
clientbound gift-list *decoder* that, per-gift, opens a `CDialog::DoModal` @0x47130E and
then emits the mode-0 NOTE_ACTION — the writer lives inside the loop body, which the
decompiler collapses; disasm confirms it.)

### Writer #3 — mode 2 (request) body @0x91D3A1
`Encode1(2)` only, then SendPacket. No payload.

### Writer #1 — mode 0 (gift send) body @0x47135E
`Encode1(0)`, `EncodeStr(...)` @0x47138F, `EncodeStr(modalText)` @0x4713A8,
`Encode1(1)` @0x4713B2, `Encode4(0)` @0x4713BB, then an 8-byte `DecodeBuffer`'d gift
blob (Src = var_18+var_14, size 8) @0x4713C8. (Gift-accept flow, not the note-send path.)

### Writer #2 — mode 1 (discard/receive) body @0x5FB443  (Atlas v72 codec = 🟡 partial)
`CMemoListDlg::SetRet(a2)` reached with `a2 ∈ {1,2}`, guarded by a YesNo confirm
(StringPool 2622). Mode byte is **hard-coded 1** regardless of a2. Encoded body:

```
Encode1(1)                    // mode = 1 (discard/receive)          @0x5FB4D5
Encode1(totalCount)           // # memos in list (*(list-4))         @0x5FB4EF
Encode1(flag3Count)           // # memos with flag(*(memo+24))==3    @0x5FB51D
Encode1(emptySlotCount)       // GetEmptySlotCount(ETC/type 4)       @0x5FB528
for each memo in list:                                              (loop @0x5FB530)
    if flag == 3 && emptySlotCount > 0:
        Encode4(memoSN)       // *(memo+8)                          @0x5FB5E4
        Encode1(flag=3)       // *(memo+24)                         @0x5FB5F9
        Encode4(amount)       // int atoi'd from memo body (mesos)  @0x5FB604
        emptySlotCount--
    else if flag == 3 && no free slot:
        (set error flag v33; entry NOT encoded; later Notice 4231)
    else (flag != 3):
        Encode4(memoSN)       // *(memo+8)                          @0x5FB55A
        Encode1(flag)         // *(memo+24)                         @0x5FB56F
```
SendPacket @0x5FB65E. flag==3 denotes a memo carrying attached mesos/item that
requires a free ETC slot to claim (extra Encode4 amount); flag!=3 is a plain
discard entry (memoSN + flag only). Variable-length, count-prefixed.
