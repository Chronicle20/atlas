# CashShopOperation Result Family — Full `OnCashItemResult` Enumeration & Codecs — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Model, enumerate, and verify **every** arm of the `CCashShop::OnCashItemResult` mode-prefix dispatcher (56 arms — 9 already modeled, 47 new) as discrete clientbound codecs across all 9 client versions, driven by a full IDA reverse-engineering pass with gms_v95.1 as the reference.

**Architecture:** This is a **mode-prefix dispatcher family** task (see [`DISPATCHER_FAMILY.md`](../../packets/DISPATCHER_FAMILY.md)). One clientbound opcode (`CASHSHOP_OPERATION`) whose leading `Decode1` byte selects one of ~56 per-mode handler arms. Work proceeds in four sequenced **waves on a single worktree**: (1) RE all 9 IDBs → `arm-catalog.md` (the sole source of wire truth) + extended `cash_shop_operation.yaml`; (2) modern-5 codecs (discrete struct + body func + `run.go` `#`-entry + round-trip test per arm); (3) modern-5 verification (byte-fixtures + pinned evidence + matrix promotion); (4) legacy codecs + verification; (5) close-out. Layer 1 (RE) gates everything — a wrong read order in the catalog poisons every downstream layer — so it has a hard review checkpoint before any codec is written.

**Tech Stack:** Go (`libs/atlas-packet`), the `response.Writer`/`request.Reader` codec pattern, `atlas_packet.WithResolvedCode`/`ResolveCode` config resolution, the `packet-audit` tool (`operations`, `dispatcher-lint`, `fname-doc`, `matrix`, `gate-check`), `ida-pro-mcp` for RE, tenant seed templates JSON under `services/atlas-configurations/seed-data/templates/`.

## Global Constraints

Every task's requirements implicitly include this section. Values copied verbatim from the PRD/design.

- **Discrete per mode (INV-1 / AP-1).** One struct per arm, even for wire-identical arms (the two wishlist arms are already split for exactly this reason). Bodyless notice/error arms are still their own `struct { mode byte }`. **Never** a shared-by-shape struct.
- **Config-resolved mode byte (DOM-25 / INV-2 / AP-2 / AP-3).** No `mode: 0x…` literal in any constructor; no `func(_ byte)` in a body-func file. The mode byte is resolved from the tenant `operations` table via `atlas_packet.WithResolvedCode("operations", FIXED_KEY, func(mode byte)…)`; the constructor's first param is `mode byte` and the body func passes the **resolved** value through.
- **Config-resolved reason byte (INV-2 extension).** Failure arms resolve their reason from the writer's `"errors"` table via `atlas_packet.ResolveCode(l, options, "errors", message)`. Never a Go literal reason byte.
- **No caller-supplied operation (INV-3 / AP-4).** No exported `*Body(` func takes an `op`/`code`/`mode`/`key` param, nor any param (whatever its name) that flows into the `WithResolvedCode("operations", …)` key. The arm maps to ONE operation → the key is a fixed const. (A `message string` param flowing into the `"errors"` key is allowed — it is not the operations key.)
- **Version gating idiom (FR-2.4).** Version-divergent fields gate with `ctx`/`MajorAtLeast`/`MajorVersion()` idioms consistent with `libs/atlas-packet`, **never** a raw `> N`. Any gate straddling two versions needs a verified byte-fixture on BOTH adjacent versions (`gate-check`). **No wire change to an already-verified arm/version** except to fix an RE-discovered defect (documented on-branch).
- **Grounding — no inventing (PRD §8, CLAUDE.md).** Every mode byte, field, and arm-presence fact comes from the IDB (v95 reference) or a checked-in export — never from memory or general MapleStory knowledge. An unresolved fname is a **stop-and-ask escalation**, never a guess. `n-a` is proven only by full case enumeration at the switch address, never assumed.
- **No silent drops / no stubs (PRD §8).** Every supported arm's key must land in **every** supporting version template (else the server drops the packet at emit). No arm is added with a `TODO`/hardcoded placeholder mode. An arm is either fully modeled + enumerated + verified, or recorded `n-a`.
- **Determinism.** Template `writers`/`handlers` arrays keep strictly ascending `opCode` order (template-opcode-order guard). The `operations` **map** is keyed (not the writers array) and is regenerated by the tool, not hand-edited.
- **IDB discipline.** Name every touched function while reversing (root dispatcher + every branch handler), using the v95 names as baseline (`OnCashItemRes…`); `idb_save` after naming. Confirm the IDA instance matches the version before reading.
- **Test helpers.** Use the package's existing Builder/fixture helpers (`pt.Variants`, `pt.Encode`, `pt.RoundTrip`, `variantKey`, `bytesEqual` in `shop_operation_result_test.go`). Do NOT create `*_testhelpers.go`.
- **Scope boundary (D1).** In scope = exactly the cases in the v95 `OnCashItemResult` switch (56 arms). The sibling **separate-opcode** dispatchers (`OnCashItemGachaponResult`, `OnGiftMateInfoResult`, `OnCheckNameChangePossibleResult`, `OnCheckTransferWorldPossibleResult`, `OnChargeParamResult`, `OnPurchaseExpChanged`, `OnOneADay`, `OnNoticeFreeCashItem`, `CASHSHOP_REGISTER_NEW_CHARACTER_RESULT`, `CASHSHOP_GACHAPON_STAMP_RESULT`) are OUT — each is its own matrix row. Watch the naming trap: in-switch `…ResCashGachaponOpenDone` (IN) vs separate `OnCashItemGachaponResult` (OUT).

	for _, v := range pt.Variants {

			mode, ok := buyFailedModes[variantKey(v)]

import (
	"context"
	"fmt"

	"github.com/sirupsen/logrus"

	"github.com/Chronicle20/atlas/libs/atlas-socket/request"
	"github.com/Chronicle20/atlas/libs/atlas-socket/response"

// BuyFailed - BUY_FAILED arm (CCashShop::OnCashItemResBuyFailed): mode + reason byte.
// Discrete per-mode struct: fixes the BUY_FAILED operation key; never accepts the mode
// from the caller (the body func resolves it).
// packet-audit:fname CCashShop::OnCashItemResult#BUY_FAILED
type BuyFailed struct {
	mode      byte
	errorCode byte
}

func NewBuyFailed(mode byte, errorCode byte) BuyFailed {
	return BuyFailed{mode: mode, errorCode: errorCode}
}

func (m BuyFailed) Mode() byte        { return m.mode }
func (m BuyFailed) ErrorCode() byte   { return m.errorCode }
func (m BuyFailed) Operation() string { return CashShopOperationWriter }

func (m BuyFailed) String() string {
	return fmt.Sprintf("cash buy failed mode [%d] errorCode [%d]", m.mode, m.errorCode)
}

func (m BuyFailed) Encode(l logrus.FieldLogger, _ context.Context) func(options map[string]interface{}) []byte {
	w := response.NewWriter(l)
	return func(options map[string]interface{}) []byte {
		w.WriteByte(m.mode)
		w.WriteByte(m.errorCode)
		return w.Bytes()
	}
}

func (m *BuyFailed) Decode(_ logrus.FieldLogger, _ context.Context) func(r *request.Reader, options map[string]interface{}) {
	return func(r *request.Reader, options map[string]interface{}) {
		m.mode = r.ReadByte()

// FIXES the BUY_FAILED operation key; resolves the reason byte from the writer's

	return func(l logrus.FieldLogger, ctx context.Context) func(options map[string]interface{}) []byte {
		return func(options map[string]interface{}) []byte {
