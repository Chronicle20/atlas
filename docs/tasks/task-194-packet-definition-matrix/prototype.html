Packet Matrix — Pivot Grid

Templates only, one frozen identity column, the sorting baseline marked in place, and options surfaced as a first-class dimension. Every opcode, option shape and FName below is read from the seed templates and the audit registry.

The matrix

Rows are definitions keyed by implementation name; columns are Templates in version order. The baseline is not a separate column — the template driving row order is marked in place, amber-capped and outlined, so you can see the sort key without spending 90px of frozen width on a duplicate.

Only FName is carried as derived metadata. It is joined from docs/packets/registry/<version>.yaml on (direction, opcode) and stored nowhere.

How options surface

Options are the reason the current page is 215 stacked cards of chip clouds. They are also structurally two different things, and the matrix has to handle both: maps keyed by name (operations, failedReasonCodes, codes) where the value is the wire number, and ordered lists (types) where the array index is the wire value and the name is not even unique — CharacterMovement at v95 carries UNKNOWN at six separate indices.

Not in the row

No per-row options summary. Options should differ between versions — v12.1 supports nine movement types and v95.1 supports thirty-three, and a column that shouts about it on every row is noise you learn to ignore. Divergence is the expected state and gets no ink.

In the cell

Exactly one marker. ⌀ means this template supplies no options for a definition that a sibling template does supply them for. That is not version drift, it is an omission — the failure mode that silently breaks decoding — and it is the only options state that earns a mark in the grid.

In the drawer

A second matrix, nested. Rows become option entries — array index for lists, key name for maps — and the columns stay the same templates. Diffing types becomes reading down a column, and an entry that shifts index between versions shows up as a diagonal. This is where you go when you actually want to compare, rather than being told to.

What this immediately surfaces

Reading the CharacterMovement row above: v12.1 carries 9 movement types, v61–v83 carry 23, v84 adds FLYING_BLOCK at index 23, v87 adds a 25th, jms185 carries 33 — and v92.1 and v95.1 carry none at all. PetMovement is empty at v87.1, v95.1 and jms185 while v61–v84 all populate it.

Whether those empties are intentional needs checking against the codecs — but an empty types array is the same shape as the confirmed v79 monster-movement defect, where moves never decoded and mobs fell through the floor. Today that state is invisible; it is fourteen scroll-screens into a stacked-card form. Here it is two red marks on the baseline column of the page you already had open, which is the clearest argument for building this thing.

Per-object pages — where ancestry lives

No tenant columns in the matrix. Tenant-versus-ancestor comparison belongs on the Tenant's own Socket Handlers and Socket Writers pages, which render the same grid locked to two columns: the tenant and its inferred ancestor Template. Same search, sort, filters, drawer and dialogs; the mode switch, column picker and baseline selector are simply not there.

Cell scope, and the no-ancestor case

Cell scope

Clicking a cell rather than the name scopes the drawer to that template — the outline follows your click and every action relabels: Edit in v87.1, Mark unsupported in v87.1. Open in GMS v87.1 ↗ is the §13 deep link: it navigates to that template's Socket Handlers or Writers page with the grid filtered to this definition and the row already selected, so you land on the thing you were looking at rather than at the top of 141 rows. It disables where the definition is Undefined, since there is nothing to open. Click the definition name instead of a cell and the scope stays on the baseline.

No ancestor

Settled: if a Tenant's Region + Major + Minor matches no Template, the page drops to a single column and the ancestry features simply are not there — no manual template substitution, no empty comparison column. It is not expected to happen.
