## Note on guideline source drift

The frontend-dev-guidelines skill's `resources/architecture-overview.md`, `patterns-react-query.md`, etc. describe a **Next.js 16 App Router** app (`app/*/page.tsx`, Jest, `next-themes` "system" mode, `next/image`). This repo is actually a **Vite + React Router SPA** (`src/pages/*.tsx`, `App.tsx` route table, Vitest, no Next.js at all — see `services/atlas-ui/CLAUDE.md`). Where the two disagree, this audit follows the repo's actual, checked-in convention (`services/atlas-ui/CLAUDE.md` plus cross-referenced sibling pages), since that is the standard this PR is actually held to. The skill doc's `resources/` files appear stale and should be regenerated from the real app — flagging for whoever owns the skill, not as a task-231 defect.

## Summary

### Blocking (must fix)

- **FE-09** — Add `enabled: !!activeTenant` (via `useTenant()`) to all four events `useQuery`/`useQueries` call sites: `EventDefinitionsPage.tsx:32-35`, `EventDefinitionsPage.tsx:46-55`, `EventOccurrencesPage.tsx:94-97`, `EventOccurrenceDetailPage.tsx:63-66` (keep the existing `definitionId !== undefined` guard on `EventOccurrenceDetailPage.tsx:75` and AND it with the tenant check). Without this, a direct navigation to any `/events/*` route before the tenant context resolves fires a request with no tenant headers set.
- **FE-10** — Embed `activeTenant?.id ?? "no-tenant"` into every events query key (same four call sites as FE-09), matching the pattern at `MapsPage.tsx:51`, `ReactorsPage.tsx:59`, `MonstersPage.tsx:66`.
- **FE-14** — Add `as const` to the three query keys currently missing it: `EventDefinitionsPage.tsx:48`, `EventOccurrencesPage.tsx:95`, `EventOccurrenceDetailPage.tsx:64` and `:73`.

### Non-Blocking (should fix)

- **FE-14 (structural)** — Consider consolidating the five ad-hoc `["events", …]` key sites across three files into a single `eventKeys` factory (mirroring `rewardPoolKeys`), once the tenant segment above is added, so tenant-inclusion can't silently regress on a future edit to any one of the four call sites.
- **Custom occurrences table** — `EventOccurrencesPage.tsx`'s hand-rolled `<Table>` (via `event-occurrences-columns.tsx`) loses `DataTable`'s column sort/visibility and `headerActions` slot versus every other list page. The documented reason (row-level `data-testid`/className hook `DataTable` doesn't expose) is legitimate, but if a second page needs the same row-level hook, it's worth adding that capability to `DataTable`/`DataTableWrapper` directly rather than a second one-off table implementation.
- **Testing** — Once FE-09 lands, add a test to each of the three page suites asserting the query does not fire (or the page shows an appropriate empty/loading state) while `activeTenant` is null, matching whatever pattern the reward-pools or maps/reactors/monsters suites use for the same guard (not independently verified in this audit — check before assuming one already exists).
