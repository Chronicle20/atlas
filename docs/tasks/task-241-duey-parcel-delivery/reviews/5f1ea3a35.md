`libs/atlas-packet/parcel/clientbound/v87_test.go:16-45` defines
`wantEquipItemBytesV87()`, byte-identical to `wantEquipItemBytesV84()` in
`v84_test.go`, with inline provenance citing `GW_ItemSlotEquip::RawDecode`@

could not re-confirm this address against the live IDB (no IDA tool access —
see caveat above). What I *did* confirm:

- `grep -n MajorAtLeast libs/atlas-packet/model/asset.go` tops out at `84`
  (lines 260/605) — no gate above 84 exists anywhere in the file, so the
  report's "byte-identical to v84" claim is at least consistent with the
  codec side of the equation (there is no code path that *could* diverge v87
  from v84 unless a wire-level difference exists that the codec doesn't gate
  on — which is exactly the risk the task flagged, and exactly what I cannot
  rule out without IDB access).
- Ran a mutation test: flipped one byte in the middle of
  `wantEquipItemBytesV87()` (nDurability field) and re-ran
  `TestParcelArrivedV87WithItem` — it failed with a clear byte-diff (see
  transcript below), confirming the fixture is non-vacuous, not a
  `got == got` tautology. Reverted immediately; `git status` confirms clean.
- `TestParcelArrivedV87WithItem` and `TestParcelOpenV87WithItem`
  (`v87_test.go:186-210`, `260-283`) both attach a real item via `.SetItem`,
  hand-build `pBytes` byte-by-byte (not by calling the encoder to produce
  `want`), and assert the full wrapper output — same discipline as the batch-4
  anchor.
- `go test -count=1 ./libs/atlas-packet/parcel/...` passes (`ok` both
  packages).

**This is the one finding I cannot fully close.** The report's central claim
— that v87's asset-encoding path is byte-identical to v84's, grounded in a
fresh IDB read rather than copied prose — is exactly as strong as the
`0x502eac` three-`Decode4` citation, and I have no way in this session to
re-decompile that address myself. I flag this as **not evaluable** rather
than either passing or failing it. A controller who has IDA access to session
`c0829805` should spend one `decompile` call confirming this address before
treating the batch as fully closed.
