## Task 14 ruling — audited on the merits

The implementer kept Task 14 (propagate `parseDirectory`'s swallowed
sub-directory error; make `wztoxml` ingest failures countable), on the
grounds that it is a direct instance of the surviving FR-8 and does not
consume `diagnosis.md`, `reference-fidelity.md`'s labels, or any allowlist.

I read Task 14 as it now stands (`plan.md`, "## Task 14"). Its Files section
(`libs/atlas-wz/wz/directory.go`, a new `directory_error_test.go`,
`services/atlas-data/.../wztoxml/adapter.go`, `adapter_test.go`) names no
Reactor-specific fixture and no dependency on Task 6/7/11/12/13's outputs;
its "Interfaces: Consumes" line reads "nothing from earlier tasks." Its test
plan (`TestSubDirectoryParseFailurePropagates`) builds and corrupts a
synthetic two-level archive with `wztest`, not a reproduction of a byte
pattern found only in the (withdrawn) diagnosis. The defect class it
targets — a sub-directory parse failure silently dropping every image
beneath it with zero error to the caller — is a general defensive-parsing
gap that exists independent of whether HaRepacker's dump matched this
archive.

The one place the withdrawn narrative actually appeared was the task's
opening sentence, which called this "the enumeration-level instance of the
exact corruption class this task exists to kill" citing design §5/§6.3 (the
false 19-image theory). The implementer corrected that specific sentence in
place, labeling the design citation "historical framing," without touching
Files/Steps/test plan.

**Ruling assessed as sound.** I looked for a hidden dependency the
implementer might have missed — e.g., whether Task 14's "blast-radius
survey" (that every `wz.Open` call site already checks its error) rested on
anything from the withdrawn diagnosis — and it does not; that survey is a
static grep over call sites (`workers/runtime.go:144-148`, `:209-213`),
unrelated to the Reactor.wz byte comparison. I concur: Task 14 is correctly
kept, and the entangled narrative sentence was the only thing that needed
correcting.
