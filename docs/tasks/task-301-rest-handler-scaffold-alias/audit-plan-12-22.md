## Skipped / Deferred Tasks

**Task 18 (PARTIAL):** The plan's Step 5 for atlas-npc-conversations was an explicit, reasoned "do not delegate" instruction backed by a concrete input-narrowing argument (`fmt.Sscanf` prefix-acceptance vs. `strconv.Atoi` strict-format rejection). The implementation nonetheless added commit `cc0c55dcd`, delegating `ParseNpcId`, `ParseQuestId`, and `ParseConversationId` to the shared `server.ParseIntId`/`server.ParseUUIDId` parsers. This is a genuine, unmitigated behavior change: a path segment like `characterId=12abc` (or any numeric-prefixed npcId/questId) that previously resolved successfully via `fmt.Sscanf` will now 400 via `strconv.Atoi`. No existing test in `services/atlas-npc-conversations` exercises this edge case, so the regression is silent and would only surface in production if any caller (in-repo or external) relies on prefix-tolerant parsing for these two path segments. `ParseItemId` (which also has the `itemId == 0` rejection called out in the plan) was correctly left undelegated, so the deviation is partial, not total. Impact: low likelihood of being hit in practice (well-formed callers send exact integers), but it is exactly the kind of silent narrowing FR-4.3 was written to prevent, and the plan called it out by name specifically to avoid this outcome.
